Durable Capture First\nJSON log happens BEFORE database insert. If DB fails, lead is still recoverable from logs.\n\n### 2. Best-Effort Downstream\nEmail and webhook failures are logged but never block the response. User always sees success.\n\n### 3. Rate Limiting\nSame as existing leads endpoint: 5 req/min/IP. Protects against spam and bot abuse.\n\n### 4. Separate Endpoint\nDedicated `/api/pilot-leads` instead of reusing generic `/api/leads` (QuoteRequest). Keeps concerns separate; easier to modify pilot logic without affecting regular quotes.\n\n### 5. Explicit Role Enum\nForms are strict about role values. Makes admin filtering and reporting easier.\n\n---\n\n## Error Handling\n\n| Scenario | HTTP Status | Behavior |\n|----------|------------|----------|\n| **Invalid JSON** | 400 | JSON parse error |\n| **Missing required fields** | 400 | Field errors returned |\n| **Rate limited** | 429 | Retry-After header set |\n| **DB down** | 201 | Lead logged; email sent; DB insert failed (logged) |\n| **Email service down** | 201 | Lead in DB; email failed (logged) |\n| **Internal error (unexpected)** | 500 | Error logged; user sees \"try again\" |\n\n---\n\n## Dependencies\n\nNo new dependencies required.
